## Review the prototype

Settings path: **hold Confirm on task home → Device management → Sound reminders**. Up/Down selects Effects or Voice; tap Confirm to save. Select Preview current mode and confirm to audition, Return to management for the parent menu, or hold Confirm for task home. Default is Voice. Voice plays the phrase directly for completion, choice, error and disconnect; user-initiated stop only updates status and stays silent in both modes. The prototype saves to browser storage; device persistence is for the firmware implementation. Voice timbre is fixed to confirmed review 4; planned effect volume is 85%.

Open [the standalone HTML](../design/v1.3.0/index.html) in a modern browser. Images, a Chinese font subset and all eight WAV samples are embedded. No server or external requests are required. Tasks, battery, recording and message sending are synthetic; the prototype never connects to DSH or hardware.

1. Tap Up on the task home to enter companionship. Up/Down cycle Hello, Pet, Feed fish, 喝咖啡 (Drink coffee) and Return. Confirm runs a roughly three-second animation. Hold Confirm for 0.5 seconds to interrupt and return; hold Down for the session list.
2. Use the six external scenario cards for automatic entry, offline/reconnect, audio settings, deferred recording notifications, and a working tenth session beyond the first list page. Fast-forward advances only simulation time, without resetting inactivity or dimming.
3. Inject work events into the selected session, or add, archive, delete and resolve sessions. Diagnostics show global counts, event deduplication, priority and deferred playback. Opening content acknowledges its unread flag; merely navigating to the list does not.
4. Enable audio, then audition the four effects and four fixed Chinese phrases. Device management offers only Effects and Voice, defaulting to Voice; Confirm saves the choice locally. Its preview item plays the completion cue.

Keyboard Up/Down/Enter map to the hardware keys; hold for 0.5 seconds or use Shift + key for long presses. Focus the screen first to avoid overriding normal web form navigation. The first device key after dimming only wakes the display. Browser localStorage persistence is not an implementation of device NVS.

## Screen and navigation contract

The screen is exactly 240×320, using the existing paper/navy/blue palette and approved work characters. The companion has a 196×196 actor, connection and battery at the top, one short line and the selected action at the bottom. Scenario tools and diagnostics stay outside the device interface.

| Page | Up / Down | Confirm | Long press / return |
| --- | --- | --- | --- |
| Task home | Companion / latest reply when available | List, or current pending choice | Up: record; Down: list; Confirm: management |
| Companion idle | Cycle five items: four interactions and Return | Run action / return home | Confirm: home; Down: list |
| Interaction | No stacked action | Ignore repeated confirmation | Confirm or Down immediately cancels action |
| Session list | Select name and colored status | Relevant pending content, otherwise home | Confirm: home |
| Latest reply | Continuous scrolling of one reply | Collapse to home | Confirm: home |
| Single choice | Select, or return from confirmation | Preview, then confirm answer | Confirm: leave without answering |
| Error details | No additional action | Home | Confirm: home |
| Management | Select sound / connection / return | Open | Confirm: home |
| Sound settings | Select mode / preview / return | Save, preview or return | Confirm: home |
| Recording | No navigation | Stop and preview text | Confirm: cancel to home; Down: cancel to list |
| Transcript preview | Send / record again | Execute synthetic action | Confirm: cancel to home |

List priority is pending choice, unread error, new reply, running, then other states. Only opening the relevant reply/error clears that unread marker. A question remains pending until an answer is confirmed. The prototype shows four list rows per screen; idle decisions use every main session. There are no progression values, daily tasks or interaction voices.

## Automatic entry and interruption

Only the task home may automatically enter companionship after 120 seconds without device input. With a connected, capable bridge, every unarchived main session must have zero running work, pending questions and unread notifications. Legacy bridges retain manual companionship but cannot authorize connected automatic entry from a partial list. Offline entry is allowed with a persistent disconnected label, without claiming the computer is idle.

Reading, lists, questions, recording, management and connection pages never auto-navigate. Automatic entry preserves the dimming timer; it may coincide with the existing 120-second dim. A device key wakes the screen. Idle animation uses a slight breathing offset, blinking and occasional yawning with no more than approximately eight discrete changes per second.

While in companionship, a task/new session starting interrupts the action and opens its home. New choices, unread errors or replies open the attention list without acknowledging anything. User-initiated stop only updates the stopped status: it creates no sound, unread marker or deferred recording notification, and does not force departure from companionship. Initial/reconnect snapshots never replay historical audio: reconnect opens the list for pending items, the corresponding home for running work, or keeps companionship if idle. The external historical snapshot control demonstrates this distinction.

Thinking, tool execution and network waiting remain silent. The first event opens a one-second batch window; only its highest-priority valid cue plays, while other attention items remain visible. Stable event identities prevent repeats. A disconnect lasting five seconds becomes eligible for batching (an isolated disconnect normally plays around second six), once per outage.

Recording immediately cancels playback and defers notifications. Stop/cancel revalidates session existence, event revision, unresolved attention and connection state; resolved, archived, deleted or superseded events are discarded. Effects mode plays only effects. Voice mode directly plays the phrase for completion, choice, error and disconnect, without a preceding effect; user-initiated stop remains silent in both modes. Both modes preserve all visual markers.

Speech is the confirmed **review 4 clockwork-girl voice**: Xiaoyi, rate -12%, pitch +2 Hz with a preprocessed light metallic layer. The fixed files are 16 kHz mono PCM16, approximately 0.66, 0.96, 1.84 and 1.36 seconds. The added disconnect phrase uses the same base voice and processing; generator: `make_disconnect_voice.py`, metrics: `voice-extra/manifest.json`. No runtime synthesis or voice DSP is required. Device loudness and recording/playback transitions remain untested. Planned effect volume is 85%; browser playback is not a device acoustic measurement. Source/processing parameters are in `audio-review-v4/manifest.json`; actual prototype payloads and hashes are in `asset-manifest.json`.

All assets are in [design/v1.3.0](../design/v1.3.0); [asset-manifest.json](../design/v1.3.0/asset-manifest.json) records hashes, sizes and audio metrics.

## Validation and reproduction

A new two-mode storage schema prevents old three-mode values from overriding default Voice; invalid values also fall back to Voice. Prototype automation covers default Voice, persistence of both modes, actual audio file routing, silent user stops in both modes and during recording, repeated stop suppression, the four interactions, repeated confirmation and long-press cancellation, idle/dimming, off-page work, legacy bridge, offline/reconnect, archive/delete/add, unread flags, audio priority/deduplication, recording deferral/invalidation, keys, battery and saved modes. All eight active WAVs actually decode and complete browser playback; this does not certify subjective sound quality or device acoustics. Checks also cover exact 240×320 size, no horizontal overflow at 360 px width, loaded images, zero page exceptions and no external requests.

Install Pillow, fonttools and brotli, then run `design/v1.3.0/build_prototype.py --font <SourceHanSansSC-Normal.otf>`. Install Playwright and run `node design/v1.3.0/check_prototype.cjs`. `EDGE_PATH` optionally selects an installed browser; `PROTOTYPE_REPORT_DIR` selects the report directory. Without `--font`, the builder reuses the inspected subset; after copy changes, regenerate with the font source to recheck coverage.

**Build:** standalone HTML/assets generated; no new firmware build. **Host tests:** see delivered `validation/validation.json`. **Device tests:** not run. **Unverified:** physical loudness, amplifier recovery, recording exclusion, LVGL glyphs/memory/long-term stability, real bridge global summary and event stream. These belong to stages 2–4 after design approval.

The task screen shows a Confirm / List key hint at the upper right beside the battery. A single footer row shows Up / Companion, Hold Up / Voice, and Down / Reply, with the voice shortcut emphasized. Hold Confirm still opens management. Discovery does not depend on help outside the device screen.

Overflowing task-home titles scroll automatically: pause 1.5 seconds, move at about 22 pixels/second to the end, pause 1.5 seconds, then return to the start and repeat. Short titles stay still.
