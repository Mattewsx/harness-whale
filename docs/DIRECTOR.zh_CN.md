# 画面调度层

[English](DIRECTOR.md)

`device-firmware/main/whale_director.c` 决定屏幕由哪个页面占用、什么时候切换。它是纯逻辑，不依赖 ESP-IDF、LVGL 和 BLE。`whale_app.c` 先取一份状态快照（`whale_director_in_t`）交给调度层，再执行它的决定：打开页面、请求快照、取消语音。思路借鉴 Clawdmeter 的 director 设计，只借鉴做法，不用它的代码和协议。

第一版只把现有规则集中到这里，行为不变。待处理队列是在它上面做的第一个功能。之后的功能（着急和庆祝情绪、成就徽章）也把规则加在这里，把不变式加进模糊测试。

## 谁占用屏幕

从高到低：

1. 需要你处理的工作：提问、审批、未读回复。
2. 语音：录音、上传、提示音播放。
3. 你正在看或正在操作的页面。
4. 陪伴互动。
5. 日常待机动作。
6. 待机画面：今日小结或时钟。

## 规则

| 函数 | 条件 | 结果 |
| --- | --- | --- |
| `whale_director_desk` | 在主页或会话页，空闲 `WHALE_DESK_IDLE_MS`（2 分钟），所有会话可确认空闲，没有语音、陪伴动作以及待播或播放中的徽章庆祝 | 进入待机画面 |
| `whale_director_desk` | 在待机画面，已连接且就绪，但桥接器不支持全局摘要（能力位 11） | 回主页 |
| `whale_director_offline` | 离线，不在常驻页，空闲 `WHALE_POWER_OFF_MS`，没有需要保持的事（语音、音频、提示音合并、配对、解绑） | 回主页（取消语音） |
| `whale_director_summary` | 在待机画面，收到有效全局摘要，有待回答的问题 | 打开待处理队列 |
| `whale_director_summary` | 在待机画面，收到有效全局摘要，只有未读 | 打开需处理列表 |
| `whale_director_summary` | 在待机画面，有效摘要里只有运行中的会话 | 打开那个会话 |
| `whale_director_trigger` | 在待机画面，收到实时提醒 1（提问） | 打开待处理队列 |
| `whale_director_trigger` | 主页闲置 `WHALE_QUEUE_IDLE_MS`（10 秒），收到实时提醒 1，没有语音和陪伴动作 | 打开待处理队列 |
| `whale_director_trigger` | 在待机画面，收到实时提醒 2～4 | 打开需处理列表 |
| `whale_director_trigger` | 在待机画面，收到触发 5（开始干活） | 打开那个会话 |
| `whale_director_key` | 在待机画面按任意键 | 回主页 |
| `whale_director_queue` | 回答被接受的结果页已显示 `WHALE_QUEUE_NEXT_MS`（1.5 秒），答题之后到达的摘要仍有待回答的问题，没有语音 | 打开待处理队列 |
| `whale_director_result_key` | 在这个结果页按确认，摘要条件同上 | 打开待处理队列（否则和以前一样回到会话） |
| `whale_director_screen` | 在操作页，或已连接且有进行中的会话（陪伴、换装、徽章、待机页除外） | 保持亮屏 |
| `whale_director_screen` | 语音、音频、提示音合并、配对、解绑 | 不允许睡眠 |
| `whale_director_badge_start` | 有待庆祝的新解锁徽章位掩码，且回到安静的主页（无语音、陪伴动作或邀请） | 启动单次 4 秒徽章庆祝（单枚显示名称，多枚合并为“解锁 N 枚新徽章”） |
| `whale_director_activity_set` / `whale_director_activity` | 主页待机动作 | 按心情（5 分钟内）或昼夜选动作组，下一个动作不与当前重复 |

## 情绪

`whale_director_feel` 决定鲸鱼娘在主页和列表页上方的情绪。目前是占位美术：用现有姿态加动作和一句话。

| 情绪 | 条件 | 表现 |
| --- | --- | --- |
| 庆祝 | 会话完成（实时提醒 3）或徽章庆祝启动，持续 `WHALE_CELEBRATE_MS`（4 秒） | 开心和挥手姿态交替、上下跳，"任务完成啦！"、"解锁徽章 · <名称>"或"解锁 N 枚新徽章" |
| 着急 | 有问题等了 `WHALE_ANXIOUS_MS`（2 分钟），这段时间也没按过键 | 等待姿态、左右晃，"有 N 个问题在等你" |
| 很着急 | 同上，满 `WHALE_VERY_ANXIOUS_MS`（5 分钟） | 晃得更快，"还在等你，来看看好不好？" |

着急要求已连接、摘要有效且新鲜，从"第一个问题开始等待"和"最后一次按键"里较晚的那个算起。庆祝期间庆祝优先。其他页面，以及语音、陪伴动作、邀请期间都保持平静。

"打开待处理队列"先协商能力位 17，再通过 `0x10` 末字节 3 请求独立的先来先答快照。桥接器把所有设备可回答的问题排到最前，按到达顺序排列，包括已读未答、原本在普通列表八条窗口之外的问题。看过不等于答完，也不会重新点亮已读角标。普通列表的排序 2 保持未读优先，排序 0 沿用当前顺序翻页。旧设备不请求队列排序；旧桥接器不支持能力位 17 时，待机／结果页回退普通列表，闲置主页保持不动。

设备直接打开第 0 行。没有可回答的问题时（比如只剩电脑端问题，或最后一道已归档），待机画面和结果页落到列表，闲置的主页保持不动。其他页面不会被打断，列表角标照常显示数量。

断线或重新握手会取消尚未完成的自动跳题；响应中的桥接器 epoch 改变时，也只回到列表／主页，不自动打开问题。新的能力协商和重连基线不会被误当成旧的队列响应。

"可确认空闲"指：离线，或 30 秒内收到的有效全局摘要里没有运行、等待和未读的会话。

## 不变式

带种子的模糊测试在每个随机事件后检查：

- 只从主页或会话页进入待机画面，必须过了空闲时间、所有会话空闲，语音和陪伴动作期间不进入。
- 有等待或未读的摘要、任何实时提醒，都会把待机画面切回工作页面；有待回答的问题时打开队列。
- 主页闲置满 10 秒才弹出新问题，语音和陪伴动作期间不弹。
- 队列只在回答被接受的结果页显示过之后前进，语音期间不前进，并且要等答题之后到达、仍有待回答问题的摘要。
- 结果页按确认，只有确实还有问题在等时才打开队列。
- 庆祝必须有会话完成或在安静主页启动的徽章解锁庆祝，4 秒后一定结束。
- 只有确实有问题在等、等待时间和未按键时间都超过阈值时才着急。
- 情绪只出现在主页和列表页，语音、陪伴动作和邀请期间不出现。
- 工作不会抢占其他页面：列表、正在读的回复、答到一半的问题、语音和设置都不会被打断。
- 按键一定离开待机画面。
- 离线规则只在离线、过了息屏时间、停在操作页时触发，不会打断语音、音频、配对和解绑。
- 每轮之后，离线的操作页不会停留超过息屏时间。
- 连上旧桥接器时不会停在待机画面。
- 陪伴、换装、徽章、待机页不会让屏幕常亮。配对、解绑、语音期间一定不睡眠。
- 不闪：调度层刚选的页面在下一轮保持不变。
- 同样的输入永远得到同样的结果。

## 测试

- `device-firmware/tests/test_whale_director.c`：每条规则的表驱动测试，然后用 300 个种子、每个 4000 个随机事件驱动一个简化的应用模型。失败时打印种子、状态和最近 48 个事件。用 `WHALE_FUZZ_SEED=<种子>` 复现，用 `WHALE_FUZZ_SEEDS`、`WHALE_FUZZ_STEPS` 跑更久。
- `device-firmware/tests/test_whale_app.c` 里的 `test_random_app_events`：200 个种子、每个 3000 步，向完整的 `whale_app.c` 喂随机 BLE 帧（部分是格式正确的全局摘要和实时提醒）、按键、连接变化、语音和时间跳变，检查状态范围以及待机画面从不遮住工作。用 `WHALE_APP_FUZZ_SEED=<种子>` 复现。
- `tools/validate.sh --static` 正常跑一遍，编译器支持时再在 AddressSanitizer 和 UBSan 下跑一遍。

`test_whale_app.c` 里的 `test_pending_queue` 把队列从头走一遍：回答被接受、旧摘要和新摘要、自动打开下一题、按确认、各种回退、主页弹出。桥接器的排序由 `tests/test_companion_cues.py` 里的 `test_pending_queue_is_first_in_first_out` 覆盖。

尚未覆盖：整个 app 的随机测试仍然很少进入提问页，因为那需要完整的提问交互。
