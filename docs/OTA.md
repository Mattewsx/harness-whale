# 蓝牙 OTA 无线升级（v1.4 起）

v1.4 起，鲸鱼固件可以通过 BLE 从电脑推送应用固件，设备上确认后写入空闲槽，校验通过才切换启动槽；新固件首次启动要通过自检，否则自动回到旧版。

## 一次性迁移：v1.3.x → v1.4 必须整片 USB 刷写

旧版分区表只有一个 0x7F0000 的 `factory` 分区，没有 OTA 槽，所以**从 v1.3.x 升到 v1.4 必须用完整镜像整片刷写一次**（`installer/flash_firmware.py`，写入 0x0）。这一步会擦除 NVS：蓝牙配对和音效设置会被清空，刷完后需要在电脑和设备两端重新配对（先在 Windows 蓝牙设置里删除旧的 HARNESS-WHALE）。

`docs/UPGRADE.md` 里的“只写 0x10000 应用镜像”路径只适用于 v1.3.x 的旧布局，**不能用于 v1.4**：v1.4 的应用在 0x20000，素材在独立分区，旧应用镜像也不能写进新布局。

迁移之后的版本升级都走 BLE OTA，不再需要 USB。

## 新分区表

| 分区 | 类型/子类型 | 偏移 | 大小 | 用途 |
| --- | --- | ---: | ---: | --- |
| `nvs` | data/nvs | `0x9000` | `0x6000` | 配对、设置（位置与 v1.3 相同） |
| `otadata` | data/ota | `0xF000` | `0x2000` | 当前启动槽与回滚状态 |
| `phy_init` | data/phy | `0x11000` | `0x1000` | PHY 数据 |
| `ota_0` | app/ota_0 | `0x20000` | `0x280000`（2.5 MB） | 应用槽 A |
| `ota_1` | app/ota_1 | `0x2A0000` | `0x280000`（2.5 MB） | 应用槽 B |
| `assets` | data/0x40 | `0x520000` | `0x2D0000`（2.81 MB） | 素材包（鲸鱼姿态、陪伴图、提示音） |
| `coredump` | data/coredump | `0x7F0000` | `0x10000` | 预留给以后的崩溃现场留存，本版不启用 |

v1.3.1 的应用是 4,858,464 字节，其中约 2.74 MB 是嵌入的素材，两个槽放不下。v1.4 把 `poses.rgb`、`companion.rgb`、`cues.pcm` 打成素材包（`tools/make_whale_asset_pack.py`），放进 `assets` 分区，由固件通过 mmap 读取。应用本身约 2.1 MB，单槽余量约 15%；素材包 2,743,146 字节，分区余量约 200 KB。`coredump` 现在就预留，是为了以后启用崩溃留存时不必再整片重刷。

**素材包不随 OTA 更新。** 每个应用镜像都记录了自己需要的素材包 SHA-256（镜像里的 `WHALE-ASSET-PACK:<sha256>` 标记）。如果某次升级改了素材，就只能再整片 USB 刷写一次；电脑工具和设备都会在开始传输前拒绝素材不匹配的镜像，避免装上后才发现。

## 安全与校验

- OTA 走独立的 GATT 特征值 `13b50204-663a-48c5-a224-37c1c2569080`，和 2.x 状态协议互不影响；和命令特征值一样要求已配对、加密且经过认证的链路。
- **每次升级和回滚都必须在设备上按确认键**；长按拒绝，60 秒不操作自动取消。电量低于 20% 或正在录音时，设备直接拒绝。
- 传输结束后依次检查：整包 SHA-256 与开始时声明的一致；ESP-IDF 镜像校验（`esp_ota_end`）；镜像的项目名必须是 `FoloToy-AI-Passport`，版本号必须是设备上确认过的版本。任一项不通过，启动槽不变，旧固件照常运行。
- 本版没有固件签名（未启用 Secure Boot）。安全边界是“已配对的电脑 + 设备上人工确认”。

## 回滚

- 启用了 `CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE`。新固件第一次启动处于“待确认”状态，会完整校验一遍素材包；素材不匹配会立刻回滚。
- 与电脑建立加密认证的蓝牙链路后，才把新固件标记为有效。在此之前如果崩溃或重启，bootloader 会自动回到上一版。
- 手动回滚：`python harness/tools/whale_ota_cli.py --rollback`，设备上确认后切回另一个槽里的旧版本。

## 使用

桥接器在运行并已连上设备时：

```powershell
python harness/tools/whale_ota_cli.py --info
python harness/tools/whale_ota_cli.py .\Harness-Whale-v1.4.0-ota.bin
```

只接受应用镜像（CI 产物 `FoloToy-AI-Passport-ota.bin`，发布名 `Harness-Whale-vX.Y.Z-ota.bin`），8 MB 完整镜像会被拒绝。镜像旁有 `manifest.json` 时会核对其中 `ota.sha256`。桥接器没运行时，可以加 `--direct` 让工具自己连接（设备同时只接受一个连接）。

推送过程中设备显示进度，长按确认键可以取消。完成后设备在约 1.5 秒后重启，桥接器会自动重连；重连成功即视为自检通过。之后用 `--info` 看到 `Running` 为新版本、没有 “self-test pending” 就完成了。

## 线上格式

所有整数小端。电脑 → 设备（写或无响应写）：

| 操作 | 内容 |
| --- | --- |
| `0x01` BEGIN | `u8 格式=1, u32 大小, sha256[32], 素材包ID[8], u8 版本长度, 版本` |
| `0x02` DATA | `u32 偏移, 数据[1..236]` |
| `0x03` END / `0x04` ABORT / `0x05` INFO / `0x06` ROLLBACK | 无内容 |

设备 → 电脑（同一特征值通知）：

- `0x81` STATUS：`u8 状态, u8 错误码, u32 偏移`。状态：0 空闲、1 等待确认、2 接收中、3 校验中、4 完成、5 失败、6 已取消、7 等待回滚确认。错误码见 `device-firmware/main/whale_ota_core.h`。
- `0x85` INFO：`u8 格式, u8 标志(1 待自检/2 可回滚/4 素材有效), u32 槽大小, 素材包ID[8], 运行版本, 另一槽版本`（版本为长度前缀字符串）。

流控：设备每收满 2 KiB 回一次 STATUS；电脑在途数据不超过 4 KiB。无响应写被丢弃时，设备回一次 `错误码 8` 和期望偏移，电脑从该偏移重发；窗口末尾丢包时电脑超时后从上次确认处重发。需要 MTU ≥ 247（Windows 默认协商值）。

与协议 2.3 大帧的关系：OTA 不使用 2.x 消息类型和分片器，大帧改动不影响 OTA；OTA 自己按 MTU 使用 236 字节的数据块。
