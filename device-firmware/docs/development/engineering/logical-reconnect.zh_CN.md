# BLE 逻辑重连

Windows 可能在桥接器关闭 GATT 客户端后保留物理 BLE 连接。新客户端的协议序号重新开始，而设备未必收到 GAP 断开事件；若继续用旧序号状态拒绝新 HELLO，协商只能等物理链路真正断开后恢复。

因此，完整的传统 `0x01` HELLO 是逻辑会话边界：帧版本 2、单片、10 字节消息体、协议 2.2、六个必需能力位全部置位、收发帧长至少 20。它先清除易失的接收序号、重组状态及旧大帧授权，再执行正常握手。重复有效 HELLO 可重新获得 ACK；格式错误、不支持或不完整的 HELLO 不绕过正常序号检查；其他消息仍抑制重复。

该边界不清除 NVS、配对、徽章进度或持久化题目身份。命令仍须来自已认证的绑定连接。Python 与 C 接收器实现相同边界。桥接器在原有八秒期限内每秒重试 HELLO，协商成功即停止。

验收须覆盖物理链路未断开的重连、首个 ACK 丢失、普通消息重复抑制及已保存题目身份重放。主机检查不能代替 Windows 与设备的实际重连测量。
