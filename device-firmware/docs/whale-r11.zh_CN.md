# R11.4：任务提醒与语音回复

R11.4 在 R10.4 基础上开发，分支为 `feature/r11-voice-input`。公开的 v0.10.1 附件保持原样。请安装本分支配套插件与桥接器；必须包含 `voice.ts` 和 `whale_voice.py`。安装器将固定版本的 FFmpeg 解码器安装在独立 Python 环境中。无需配置 Wi-Fi 或云端语音密钥。

## 上手步骤

1. 在已绑定电脑运行配套插件与桥接器，在 DSH「插件 → 语音输入」启用本地 SenseVoice 并完成资源准备；显示“本地资源已准备，录音时自动唤醒”即可使用。更新电脑端插件后完全退出并重启 DSH；识别服务或音频连接未就绪时设备会提示。
2. 进入任务主页，长按 ↑，就绪检查后自动开始录音。短按 ↑ 不再展开完整标题。对着设备说话，再按确认结束，↑ 取消，最长 60 秒。
3. ↑↓ 阅读识别文字，确认进入“发送／重新录音／取消”。选择发送后才会发到录音时锁定的会话；正在工作的会话会排到下一轮继续，不中断当前任务。
4. 看到已发送或已排队后确认返回。已有问题仍按原方式作答。结果不明确时，确认只查询原消息，不重复发送。除正在发送外，长按确认可退出语音页。

## 提醒与保留功能

任务列表仅显示任务名称与状态，不显示编号或回复摘要。进行中用蓝色，等你回答用琥珀色，完成／新回复用绿色，出错用红色，待命／停止用灰色；选中行使用对应浅色保证对比。

打开列表或翻组时按“等你回答 → 未读错误 → 有新回复 → 进行中 → 其他”排序，同级保持原顺序，打开列表先定位到最优先的任务。停留期间只更新状态，不因提醒变化突然重排；查看或处理后，下次打开列表恢复相应优先级。列表刷新完成前暂不接受选择，离线时仍可浏览缓存列表。

任务列表区分“有新回复”“等你回答”和“出错 · 未读”。成功显示回复首段后才清除该版本的新回复标记；进入出错任务清除未读提示，但保留出错状态。浏览列表不会清除标记。问题在作答或取消后才解除。旧版固件仍只接收原有行标志位。

已读记录保存在电脑本地应用数据目录的 `HarnessWhale/read-marks.json`（无该目录时使用 `~/.local/share`），以会话标识的哈希为键，仅含修订标识，不含回复正文。记录有数量上限，桥接器重启后保留。归档、删除会话继续排除。保留电量、最近回复缓存与连续滚动、真实 Todo 进度，以及 85% 音量、150 毫秒完成音。录音期间外设工作线程暂缓播放声音。

## 传输和异常处理

加密绑定的 BLE 连接新增尾号 `0203` 音频通知通道，每帧 62 字节：12 字节编号、序号和采样信息，加 50 字节 Opus。编码为 16 kHz 单声道、20 ms 帧、20 kbit/s 固定码率、复杂度零，要求 ATT MTU 至少 67。设备最多缓存 100 帧（两秒），丢包重传；缓存满或录音不完整时明确失败。边说边传，停止后在电脑解码并本地识别，不是实时逐字识别。

协议沿用 2.2，协商语音能力位 512 和提醒能力位 1024。十六进制消息 `40`–`47` 分别用于准备、状态与文字、编码头、结束、取消、发送、查询和累计确认；`4a` 确认已读修订。识别文字走原有批量通道。会话、桥接器周期与录音编号共同隔离过期结果。

插件向自己管理的子进程提供需认证的临时本机服务，令牌仅通过进程环境传递，不记录或提交。音频只放内存，处理结束或取消后释放。草稿十分钟无操作后过期，识别文字上限为 1,800 UTF-8 字节；过长或无效结果需重录。音频和文字不写设备 NVS。

发送采用固定消息编号，通过串行回执检查及 DSH 持久收件事件防止重复，包括消息已被消费或服务重启后的重试。会话恢复复用 DSH 控制器，保留原配置和归属。发送结果未知时若桥接器周期也变化，须在电脑检查原会话；设备不能自动核对旧传输身份。断线不能续传未完成的录音；已完成草稿可在设备和桥接器持续运行时跨 BLE 重连保留，不能跨设备或桥接器重启恢复。

## R11.2 录音启动修正

固定使用的 `esp_audio_codec` 2.6.2 返回原始 Opus 帧，`codec_spec_info` 留空。R11.1 错误地要求该可选字段包含 `OpusHead`，因此在打开麦克风前就退出。R11.2 由应用构造 RFC 7845 单声道封装头，改为校验编码器实际格式。录音日志记录失败阶段，不含音频、识别文字、会话或配对数据。

该固定版本 C3 VOIP 编码器的延迟为 `Fs/400 + Fs/250`：16 kHz 下 104 个采样，换算为 Ogg 48 kHz 时钟下 312 个采样；已核对匹配 R11.1 ELF 中的 `opus_encoder_init` 与 `opus_encoder_ctl(OPUS_GET_LOOKAHEAD)`。结束时补一个静音帧输出延迟中的语音，电脑端裁剪至实际采样长度。修改编码库版本或应用模式前必须重新验证此假设。回归测试覆盖空附加信息、封装头和尾帧、十处启动／采集故障、取消及失败后重试。

R11.1 实机已确认列表正常，但 Windows 保留了旧 GATT 服务缓存。电脑取消配对、设备解除绑定后，重新核对数字完成配对，音频特征及订阅恢复，MTU 为 247。升级后若本地识别已就绪而音频通道仍缺失，可按此方式重新配对。R11.2 没有变更蓝牙服务，已修复的绑定可以保留。R11.2 麦克风采集与实时编码仍待实机验收。

## R11.3 编码任务栈修正

R11.2 已完成麦克风初始化，但编码时重启。匹配 ELF（`387fe572b9fa82d2d2c6837784696a24966e68a079d136892b9efb6d741099c8`）将栈保护异常定位到 `silk_encode_frame_FIX` 调用的 `silk_NSQ_c`。原外设任务栈为 16 KiB；触发异常时已使用 18,032 字节，后续 NSQ 局部缓冲和 LPC 子函数使该路径约需 19,696 字节。这是该路径的最低需求分析，不代表覆盖所有编码分支。

R11.3 仅将外设任务栈调至 24 KiB，增加 8 KiB；蓝牙／显示任务栈与两秒重传窗口不变。第一帧、每秒和结束时记录空闲堆及最低栈余量，ESP-IDF 的栈水位单位为字节。余量低于 2 KiB 时退出录音并释放资源，不再进入下一帧；硬件栈保护保持开启。测试覆盖低余量退出与恢复重试。该检查不能证明首帧安全，实机仍须使用不同语音、1／10／60 秒录音、连续重录和界面／蓝牙活动验证余量。

## R11.4 图形内存实际预算修正

R11.3 在采音前以 `audio_init / ESP_ERR_NO_MEM` 退出，I2S RX 的 DMA 缓冲分配失败，历史最低空闲堆为 8,316 字节。其实际 ELF 中的 LVGL `work_mem_int` 内存池为 65,536 字节。锁定的 LVGL 9.6 已弃用 `CONFIG_LV_MEM_SIZE_KILOBYTES=32`，该值被字节配置默认值 `CONFIG_LV_MEM_SIZE=65536` 覆盖。原生渲染测试使用的是 32 KiB，因此此前主机测试没有暴露这一固件配置差异。

R11.4 改用 `CONFIG_LV_MEM_SIZE=32768`，回收 32 KiB，不改显示 DMA 缓冲、32 段回复缓存、两秒音频窗口、编码质量和 24 KiB 外设任务栈。新增 UI 编译期断言，以及检查最终 sdkconfig 和实际 ELF 内存池符号的构建校验；回归样例拒绝旧 KB 配置、64 KiB 默认值和配置／链接结果不一致。固件现在采用既有原生渲染测试预算，DMA 分配、编码栈余量及持续录音仍须在 R11.4 实机验证。

## 验证及实机验收

自动测试涵盖电脑真实 Opus 编解码、乱序／重复／丢包、C 端有限重传窗口、文字确认、只查询恢复、持久发送去重、归档与问题拒绝、已读修订持久化、固件按键状态、中文字库、原生 LVGL 渲染，以及已有回复、单选和会话回归。测试仅使用合成内容，不向真实会话发送消息。

完整 ESP-IDF 校验产出可从 0x0 刷写的合并镜像及匹配 ELF/MAP，准确哈希与结果见交付报告。编译与主机测试不能替代麦克风采音、音频切换、ESP32-C3 实时编码、蓝牙吞吐及真实 DSH 识别投递的实机验证。获得批准后测试 1／10／60 秒语音、取消、重连、归档、重复确认、运行中任务、电量和完成音。合并刷写可能重置绑定；保留 NVS 时按升级文档采用兼容的应用升级。未经批准不刷机。
